# CPU comparison and implementation status

Updated 2026-10-01. This report compares `feat/scalability-input-improvements`
with HemePure CPU commit `0bf67b16b23b41a06507810337a445f9916d62bf`.
The implementation follows HemeLB base `c8c78cb8`. GPU implementations are
outside this comparison.

The nine priorities now have code and local validation. The remaining limits
are native x86 vector execution, cluster-scale measurements, optional RBC
build dependencies, and broader physical validation. This branch has an
engineering and tooling lead and was faster on the measured small cylinder.
That does not establish a universal speed, memory, or accuracy advantage.

## Where HemePure still has an advantage

Its CPU deployment and scaling experience is broader than the local validation
performed here. The source README describes large CPU runs; the underlying
publication and scaling claims were not independently audited in this task.
This branch's largest comparative rank count remains local, not an HPC result.

HemePure contains native AVX implementations. The branch now contains optional
AVX2/AVX512 paths, but this arm64 host cannot execute them natively. Compilation
and hardware-skip behavior were checked; comparative vector speed is missing.

Some model details differ deliberately: sponge overlap uses the nearest outlet
instead of multiplying overlapping factors; passive tracers write CSV rather
than legacy particle XDR; malformed inputs are rejected. Supported legacy input
and checkpoint loading is preserved, but every historical file or experimental
build combination is not claimed to work. `windkessel/GKmodel` remains a case/source
mismatch, not an alias for WK2. Shared experimental virtual-site and active-colloid
code remains outside the validated model set.

The remaining HemePure CPU parser/model gaps found in the source audit are now
covered: periodic file velocity, weighted read/write, initial coupling timestamp,
legacy passive-tracer spellings and boundary rules, normal traction, wall extension,
and explicit wall/inlet and wall/outlet combinations. HemeLB's existing collision,
non-Newtonian, rigid-wall, pressure/velocity and convergence options remain.
See [CPU model parameters and limits](../user/cpu-models.md).

## Executed validation

The default D3Q15/LBGK/simple-bounce-back pressure build passed all six CTest
targets. A multiscale build with MPWide also passed all six, including mock
coupling tests in the C++ suite. Optional D3Q19 builds cover Yang, elastic walls,
LBGK/TRT/LES sponge, velocity coupling and explicit Yang corners. Their ten
model runs check positive finite distributions and 2-to-1 checkpoint continuation.
The Python tool suite passed 55 tests.

The actual HemePure v4 checkpoint test checks exact float promotion, then resumes
on 1 and 3 ranks from a 2-rank reference run. Continuation differed by zero between
the candidate rank counts. Synthetic legacy version fixtures also test offsets,
geometry/lattice mismatch rejection, and XML 3/5 units. Legacy camera-only
`visualisation` sections are ignored when loading XML 3/5; new v6 schema remains
strict. This changes no fluid parameters.

Yang at tau 0.62 became unstable on the cylinder in both implementations. The
reference aborted at update 805. The candidate now rejects tau below 0.8 with a
named error rather than relying on a short smoke test. At tau 0.8, a 3000-update
reference/candidate comparison passed the preset tolerances. Maximum differences
were 3.882632872320713e-06 Pa and 2.0023435354232788e-08 m/s. This does not imply stability on
every geometry at tau 0.8 or higher.

The independent Poiseuille check uses fixed 5% normalised RMS tolerance and
requires the finer grid to improve. At tau 0.8:

| Voxel size (m) | Time step (s) | Updates | Fluid sites | Normalised RMS velocity error |
| :--- | :--- | :--- | :--- | :--- |
| 0.0001 | 0.00025 | 1200 | 2400 | 0.043259937316179276 |
| 5e-05 | 6.25e-05 | 4800 | 18960 | 0.01475728489458561 |

The sponge diagnostic runs a finite viscous pipe with a 1 Pa pulse and measures
plane-averaged characteristic pressure in fixed incident/returned windows.
The returned-to-incident peak ratio was 0.38293850448908706 without sponge and
0.3565071450885767 with LBGK sponge. This is one finite-pipe diagnostic, not a calibrated
reflection coefficient or a guarantee for other outlets.

## Matched local CPU measurements

Machine: Apple M5, macOS 27.0. Both solver binaries are arm64, compiled with
AppleClang 21.0.0.21000101, Release `-O3 -DNDEBUG`, Open MPI 5.0.9,
D3Q19/LBGK/BFL/Nash pressure, scalar paths and NEUTRAL cost weights.
The reference uses C++11 and candidate C++20. HemePure needed a forced `cstddef`
include and macOS logging portability fixes; its fluid equations were unchanged.
The benchmark Python runs under Rosetta, so its platform string reports x86_64;
that string is not the solver binary architecture.

The shared cylinder has 2400 fluid sites, voxel size 0.0001 m and time step 0.0001 s,
3000 updates, constant pressure difference 1.333223874 Pa, and one matched output
frame. HemePure labels that state 3000 and HemeLB 2999. No builds or tests ran
concurrently with these timing repeats. Tables give medians of three alternating
reference/candidate runs, in seconds, from the recorded measurements.

Accuracy tolerances were set before comparing: absolute pressure 5e-5 Pa,
velocity 1e-8 m/s, and relative tolerance 1e-5. All repeated comparisons passed.
Maximum pressure difference was 4.487413297837861e-06 Pa and maximum velocity difference
2.60770320892334e-08 m/s. These tolerances are combined absolute/relative checks.

HemePure reserves rank 0 when more than one rank is allocated; HemeLB uses all
ranks for fluid sites. Equal allocations therefore have different worker counts:

| Allocated ranks | HemePure fluid workers | HemeLB fluid workers | HemePure elapsed | HemeLB elapsed | HemePure loop | HemeLB loop |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | 1 | 1 | 1.0148617079999998 | 0.7422825419999999 | 0.887 | 0.6142150000000001 |
| 2 | 1 | 2 | 1.3536208750000007 | 0.760191583000001 | 1.24 | 0.631096 |
| 4 | 3 | 4 | 0.9365173329999994 | 0.5172128750000002 | 0.776 | 0.36155800000000005 |

The loop columns include monitoring and output. HemePure's phase timer is printed
to fewer significant figures; it is not compared with the candidate's pure

## Reproduce and extend the checks

[compare-cpu-solvers.py](../../Scripts/compare-cpu-solvers.py) requires installed
Python tools and inputs writing one `whole.xtr` frame at the same physical state.
It records binary/input/geometry hashes, ranks, phase timers, accuracy tolerances,
MPI/platform information and repeats. Use `--reference-rank-offset 1` when
matching fluid workers with the reviewed HemePure build, or omit it for equal
allocations. Use `--peak-rss` separately from timing runs.

[The pipe check](../../Code/tests/cpu_pipe_verification.py) needs the geometry
CLI, NumPy and PyYAML. [The sponge check](../../Code/tests/cpu_sponge_verification.py)
compares matching baseline/sponge builds. [The actual legacy checkpoint check](../../Code/tests/hemepure_checkpoint_mpi.py)
needs a built reference executable. Raw logs and JSON remain in ignored
`research/`; reproducible scripts and this measured summary are tracked.

## Remaining verification and engineering limits

- Run native scalar/SSE3/AVX comparisons on x86 hardware before claiming vector
  speed or selecting new defaults. Both distribution arrays and 64-bit neighbour
  indices remain; no measured runtime-storage reduction is claimed.
- Measure setup, restart, halo volume, imbalance and RSS on vascular geometries
  and a cluster filesystem. Active maps/octrees remain replicated, GMY coordinates
  retain the existing 16-bit per-axis limit, and header scans grow with box volume.
- The owner cache budget is 64 MiB with a minimum whole block; one larger block
  may exceed that budget. Portable restart still uses collective count exchange
  and `MPI_Alltoallv`; no large-rank restart scalability claim is made.
- Exercise external production read/write and MPWide peers. Tracers are passive
  and replicated, not a validated force-coupled particle method.
- Validate compliant-vessel accuracy, outlet reflection, stability envelopes and
  physiological waveforms for each intended study. Local conservation, limit
  tests and checkpoint continuation are necessary checks, not clinical validation.
- RBC configuration was blocked by unavailable native VTK/HDF5 dependencies;
  its existing CI jobs remain. Remote CI outcomes remain unverified.
